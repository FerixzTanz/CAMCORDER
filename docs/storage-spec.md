# 存储与锁定影像

录像、照片什么时候会被删，哪些永远不删。删除规则只写在这里和下面几处代码里，其他地方不另立规矩。

## 1. 只认自己的文件

U 盘上可能有用户自己的东西。清理只认本应用写出来的文件名：录像 `yyyyMMdd_HHmmss_<那一路>.mp4`、
照片 `yyyyMMdd_HHmmss_<那一路>.jpg`（`StoragePlan.isOwnClip / isOwnPhoto`）。

## 2. 自动清理

| 什么 | 什么时候 | 规则 | 代码 |
|---|---|---|---|
| 录像 | 每个分段写完、录制中余量不够、开录前、每小时 | 设了上限：保持「已用 + 下一段」不超上限、盘上留余量，从最旧的一组删起，正在写的那组不碰。没设上限：一个不删，空间不够就停 | `StoragePlan.decide` / `StorageGuard.enforce` |
| 照片 | 每小时 | 超了上限，从最旧的删到上限的八成 | `StorageCleanupManager.cleanupDirectory` |
| 内部存储低空间 | 每小时（只有开发者能录到内部存储） | 剩余不到 3 GB 删两成 | `StorageCleanupManager.cleanupByPercentage` |

## 3. 锁定影像（2.0.9，项目所有者 2026-10-03）

**锁定的不会被自动清理删掉，回放里也不能直接删（先解锁）。** 存储页的开关「锁定影像」，默认开。

- **锁的是文件。** 录像：回放里「锁定此刻」锁的是这一刻各路正在放的那几个文件（环视、前座舱、后座舱有几路锁几路；
  各路分段长度可以不一样，所以按文件、不按时间戳组）。照片：一次拍摄的一整组。
- **清单放在 U 盘上**，和影像同一个目录：`DCIM/EVCam_Video/locked.txt`、`DCIM/EVCam_Photo/locked.txt`，一行一个文件名。
  换盘、重装、清除数据都还在；插到电脑上能打开看。写的时候先写临时文件再改名，拔盘不会写坏一半（`FootageLocks`）。
- **三处自动清理都跳过锁定的，但锁定的照样算占用。** 没锁的删光了还不够（上限或余量），就停录，
  提示「锁定的影像占满了空间，请在回放里解锁一些」（`StoragePlan` 的 `lockedFull`，停录原因 `STORAGE_LOCKED`）。
  锁到腾不出空间就停录，不另设锁定空间的上限（项目所有者定）。
- **清单读不出来时，这一轮自动清理一个都不删**（宁可空间不够停录，也不误删锁定的），黑匣子记一笔。
- **自动清理「读清单 → 决定 → 删」整段拿着同一把锁**（`FootageLocks.guard()`），锁定 / 解锁的写入也拿着它：
  刚锁上的文件不会正好在这一轮的删除名单里。
- **回放里删除碰到锁定的**：锁定的留下、其余照删，提示「保留了 N 个已锁定的」（视频按条删、多选删，照片多选删）。
- **关掉开关**：回放里的锁定按钮收起，自动清理和回放删除都不再跳过锁定的；清单留在 U 盘上，重新打开恢复保护。
  关的时候如果锁着东西，先弹确认：「已锁定 N 个（X GB）。关闭后它们不再受保护，空间不够时会和其他录像一样
  从旧到新删除，删掉的找不回来。」没锁东西直接关。关着期间被删掉的文件从清单里拿掉，找不回来。
- **存储页「已锁定」那一行**：录像几个文件多大、照片几张多大；开关关着时注明这些不受保护。

### 回放

- 视频：控制栏「锁定 / 解锁」，说的是这一刻（各路的文件都锁着写「解锁」）。进度条正下方一条细条，
  锁定的那几段涂成琥珀色（`LockedRangeStrip`，只画不接触摸，进度条本身不动）。列表里含锁定文件的那一条写「含锁定」。
- 照片：打开一组后控制栏「锁定 / 解锁」，作用于整组。列表里锁定的组在张数后面写「已锁定」。
